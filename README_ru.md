## 📺 Kapsel в действии

```text
╭─ kapsel [pwsh] ~/Projects/Kapsel 14:32:05
╰─ ❯ git checkout -b feature/dynamic-specs
✔ 0  git checkout -b feature/dynamic-specs  ⏱ 24ms
```

> **Оберните сложность, обнажите простоту.**
>
> Продолжайте использовать свою привычную оболочку и системные утилиты, пока Kapsel добавляет единый уровень команд, контекстно-зависимое автодополнение, встроенные подсказки истории и расширяемую среду плагинов — всё изолировано внутри `~/.kapsel/`.

---

## 💡 Почему Kapsel?

Рабочие процессы разработчиков в терминале по-прежнему сильно зависят от операционной системы и используемой оболочки.

Одна и та же задача требует разных команд на Windows, macOS и Linux. Конфигурация разбросана по файлам вроде `.bashrc`, `.zshrc` и профилям PowerShell, а системы автодополнения и инструменты требуют отдельной установки и настройки.

Kapsel добавляет неинвазивный слой капсулы вокруг вашего существующего терминала:

| Проблема | Традиционный подход | Подход Kapsel |
| :--- | :--- | :--- |
| **Кроссплатформенность команд** | Различные команды и синтаксис в разных ОС | Единый командный уровень (Linux-First) |
| **Конфигурация оболочки** | Разрозненные файлы глобальных профилей | Полностью автономное состояние в `~/.kapsel/` |
| **Автодополнение** | Отдельная сложная настройка для каждого шелла | Интеллектуальное автодополнение на базе Carapace |
| **Инструменты разработчика** | Множество разрозненных утилит с разной настройкой | Единая среда плагинов в пространстве `kps` |
| **Расширяемость** | Привязка к синтаксису конкретной оболочки | Изолированная модульная архитектура плагинов |

Kapsel не заменяет вашу оболочку и системные утилиты. Он работает рядом, обеспечивая стабильную и удобную среду выполнения.

## ✨ Возможности

### 🌐 Нативное и кроссплатформенное выполнение

Используйте привычные системные команды напрямую:

```bash
git
docker
python
npm
cargo
vim
```

В то же время Kapsel предоставляет универсальный слой для часто используемых операций:

```bash
ls -la
cat package.json
rm -rf ./dist
grep -r "TODO" .
```

Встроенные команды вашей системы надежно защищены от случайного перехвата.

---

### ⚡ Контекстно-зависимое автодополнение

Kapsel интегрирован с [Carapace](https://carapace.sh) для глубокого многоуровневого дополнения:

Движок анализирует команды, аргументы, флаги и динамический контекст:

- Ветки и теги Git
- Контейнеры и образы Docker
- Ресурсы Kubernetes
- Скрипты npm
- Спецификации для более чем 1000 CLI-инструментов

Спецификации дополнения управляются декларативно и легко расширяются плагинами.

---

### 💡 Умные подсказки истории

Kapsel хранит историю в локальной базе данных SQLite и асинхронно предлагает подходящие команды прямо во время ввода.

Нажмите клавишу `→`, чтобы мгновенно применить подсказку.

Вся история и runtime-состояние остаются изолированными в песочнице Kapsel.

---

### 🛡️ Среда без загрязнения системы

Kapsel хранит свои настройки, бинарные файлы, историю, спецификации, плагины и логи строго в:

```text
~/.kapsel/
```

Он не изменяет системные конфигурационные файлы:

```text
.bashrc
.zshrc
config.fish
PowerShell profiles
```

Ваша хост-система остается чистой.

---

### 🧩 Модульная архитектура плагинов

Под пространством имен `kps` работает среда выполнения плагинов.

Плагины могут добавлять команды, интеграции, спецификации автодополнения и внешние инструменты без необходимости модификации ядра Kapsel.

---

### 🎨 Современный интерактивный интерфейс

Компактная двухстрочная карточная компоновка:

```text
╭─ ...
╰─ ❯ ...
✔ 0  ...  ⏱ 24ms
```

Статус выполнения и время исполнения в миллисекундах отображаются сразу после завершения команды. Интерфейс полностью локализован.

# 🚀 Быстрый старт

## 1. Установка

Рекомендуемый способ установки (через `pipx`):

```bash
pipx install kapsel-cli
```

Или через `pip`:

```bash
pip install --upgrade kapsel-cli
```

## 2. Запуск Kapsel

```bash
kapsel
```

Используйте терминал как обычно:

```bash
git status
docker ps
python --version
```

При необходимости используйте кроссплатформенные команды:

```bash
ls -la
cat package.json
rm -rf ./temp
```

## 3. Команды Kapsel

Инструменты доступны через префикс `kps`:

```bash
kps status
kps config
kps portal
kps ai
```

Примеры:

```bash
kps portal work
kps ai "объясни команду git rebase"
kps shore get
```

## 4. Одиночные команды

Вам не обязательно заходить в интерактивную сессию:

```bash
kps status
kps portal
kps ai "найди большие файлы в директории"
```

Это делает `kps` отличным решением для скриптов, алиасов и конвейеров CI/CD.

# 🧩 Экосистема плагинов

Kapsel спроектирован как среда, ориентированная на плагины, а не как монолитный пакет.

## Официальные плагины

| Плагин | Команда | Описание | В основе |
| :--- | :--- | :--- | :--- |
| **`portal`** | `kps portal` / `z` | Быстрый переход по каталогам на основе частоты использования | [zoxide](https://github.com/ajeetdsouza/zoxide) |
| **`ai`** | `kps ai` | ИИ-ассистент в терминале для генерации, анализа и выполнения команд | OpenAI / Claude / Ollama |
| **`init`** | `kps init` | Управление средами разработки (Node, Python, Go, Rust и др.) | [mise](https://github.com/jdx/mise) |
| **`shore`** | `kps shore` | Тестирование скорости и переключение на быстрые зеркала пакетов | [chsrc](https://github.com/AkihiroSuda/chsrc) |
| **`install`** | `kps install` | Единая установка ПО через различные пакетные менеджеры | [mpm](https://github.com/MrEiu/mpm) |
| **`alias`** | `kps alias` | Кроссплатформенная трансляция псевдонимов команд | Нативный движок |
| **`autopilot`** | `kps autopilot` | Очереди фоновых задач и управление долгими процессами | [pueue](https://github.com/Nukesor/pueue) |
| **`help`** | `kps help <cmd>` | Практичные шпаргалки и примеры использования команд | [tealdeer](https://github.com/dbrgn/tealdeer) |
| **`fuck`** | `kps fuck` | Автоматическое исправление ошибок в предыдущей команде | [thefuck](https://github.com/nvbn/thefuck) |
| **`profile`** | `kps profile` | Управление dot-файлами и конфигурацией рабочего места | [chezmoi](https://github.com/twpayne/chezmoi) |
| **`rec`** | `kps rec` | Закладки сниппетов команд, параметры и запуск | [pet](https://github.com/knqyf263/pet) |

# ⚙️ Конфигурация

Основной файл конфигурации:

```text
~/.kapsel/config.yaml
```

Просмотр и изменение прямо из консоли:

```bash
kps config
```

Открыть в редакторе по умолчанию:

```bash
kps config edit
```

Установка параметров:

```bash
kps config set ui.enable_banner false
kps config set interaction.autosuggest_sensitivity 0.2
```

Изменения применяются на лету. Подробнее в **[Руководстве по конфигурации](docs/configuration.md)**.

# 🏛️ Архитектура

Kapsel функционирует как неинвазивный слой вокруг вашей системы:

```text
                     Хост-терминал
                            │
                            ▼
                 ┌─────────────────────┐
                 │       Kapsel        │
                 │                     │
                 │ Диспетчер команд    │
                 │ Движок дополнений   │
                 │ Реестр плагинов     │
                 │ История и состояние │
                 └──────────┬──────────┘
                            │
                  ┌─────────┴─────────┐
                  ▼                   ▼
          Системные утилиты     Команды Kapsel
          git / docker / ...     kps <команда>
```

## Двухрежимное выполнение (Dual-State Execution)

- **Нативное выполнение**: Системные бинарные файлы исполняются напрямую в вашей среде с сохранением TTY, перенаправлений и сигналов процесса.
- **Выполнение Kapsel**: Команды утилит маршрутизируются через пространство `kps` и реестр плагинов.

## Безопасные пространства имен

Такие команды, как `alias`, `help`, `install`, `history`, `profile`, `ps`, `kill`, `dir`, изолированы внутри префикса `kps` и не переопределяют встроенные команды вашей оболочки.

## Организация песочницы

```text
~/.kapsel/
├── config.yaml          # Конфигурация
├── history.db           # База данных SQLite с историей команд
├── bin/                 # Бинарные файлы инструментов
├── specs/               # Спецификации Carapace
├── plugins/             # Установленные плагины
└── logs/                # Логи и диагностика
```
